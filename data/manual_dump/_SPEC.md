# Спецификация разбора таблиц ручного поиска ТТХ

Задача: превратить таблицы из `resources/Ручной поиск` (выгружены в текст рядом с этим файлом)
в единую длинную таблицу ТТХ, которую импортёр запишет в платформу как источник.

## Формат вывода

CSV, разделитель `,`, кодировка UTF-8, кавычки по RFC 4180 (значение с запятой или кавычкой
берётся в двойные кавычки, внутренняя кавычка удваивается). Первая строка — заголовок ровно такой:

```
product_slug,product_name,attr_key,value,status,source_kind,source_url,quote
```

Одна строка = одна характеристика одного продукта. У продукта столько строк, сколько у него
заполненных характеристик.

| колонка | правило |
| --- | --- |
| `product_slug` | slug из `_products.tsv`. Если сопоставить не удалось — оставить пустым и продукт перечислить в отчёте |
| `product_name` | название продукта как в исходной таблице, без изменений |
| `attr_key` | строго один из ключей таблицы атрибутов ниже. Ключей вне списка быть не должно |
| `value` | нормализованное значение, правила ниже |
| `status` | `known` для значения; `not_applicable` для «не применимо» (тогда `value` пустой) |
| `source_kind` | `vendor` / `dealer` / `analogue` / `assumption`, правила ниже |
| `source_url` | ссылка на ТТХ этого продукта из колонки источников. Если ссылок несколько — первая, ведущая на страницу изделия |
| `quote` | исходный текст ячейки или фрагмент фразы, откуда взято значение. Это подтверждение значения, его показывают в интерфейсе |

## Достоверность: пометки в ячейках → `source_kind`

Исходные таблицы помечают значения буквой в квадратных скобках:

| пометка в ячейке | `source_kind` | смысл |
| --- | --- | --- |
| `[A]` | `vendor` | сайт производителя или разработчика |
| `[B]` | `dealer` | дилер, интегратор, СМИ, отраслевой каталог |
| `[C]` | `analogue` | оценка по аналогу |
| `[D]` | `assumption` | допущение |
| пометки нет | `vendor` | если в таблице указана ссылка на сайт производителя, иначе `dealer` |

Из `source_kind` платформа сама выводит букву достоверности, отдельной колонки для неё нет.

## Что пропускать

Строку **не создавать**, если значение: пустое, `нет данных`, `не определено`, `по запросу`,
`не опубликована`, `уточнить`, `зависит от проекта`, `—`. Такие поля в платформе и так
показываются как «нет данных».

Значение `не применимо` — это осознанно закрытое поле, оно **нужно**: `status=not_applicable`,
`value` пустой, `quote` = исходный текст.

## Правила нормализации `value`

- **number**: только цифры и точка как десятичный разделитель, без пробелов, единиц и знаков.
  `1 500 кг` → `1500`; `0,75` → `0.75`; `2 700 000 ₽` → `2700000`.
- **Диапазон** (`80-120`, `1–6`, `3–5 роботов`): взять середину, а полный диапазон сохранить
  в `quote`. `80-120` → `100`.
- **«до N», «от N», «≈N», «~N», «≤N»**: взять число N, формулировку сохранить в `quote`.
- **text**: человекочитаемая фраза без служебных пометок `[A]`/`[B]`. Габариты приводить к
  виду `1044×654×380`.
- **bool**: `true` / `false`. `Да` → `true`, `Нет` → `false`, «Да, с оговорками» → `true`.
- **enum**: строго одно из перечисленных значений.
- Если в ячейке несколько чисел про разные вещи (например мощность робота и станции) —
  взять относящееся к самому изделию, остальное в `quote`.

## Сопоставление продуктов со платформой

Список продуктов платформы — `_products.tsv` (колонки: slug, name, manufacturer, availability, trl).
Сопоставлять по названию и производителю, учитывая расхождения:

- В названиях платформы бывает хвост в скобках: `Ronavi H1500 (грузоподъемность до 1 500 кг)`
  — это `Ronavi H1500` из таблицы.
- Производитель в платформе — короткая форма (`Стелкон`, `Диком-Сервис`, `Ronavi Robotics`),
  в таблице — юрлицо (`ООО "Завод Стелкон"`, `ООО «Ронави Роботикс»`). Это одно и то же.
- Название модели в платформе может быть в другой форме: `Модель А25-1720` = `Эйдос А25-1720`,
  `Инвентаризатор AI Stock Counter 12M` = `AI Stock Counter 12M`.
- Сопоставлять только при уверенности. Сомнительное — пустой `product_slug` и запись в отчёт.

## Отчёт

Помимо CSV дать короткий текстовый отчёт: сколько продуктов разобрано, сколько строк
характеристик, какие продукты не сопоставились со платформой и почему, где данные исходной
таблицы противоречивы.
