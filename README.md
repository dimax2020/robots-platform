# Процессно-ориентированная платформа роботизации

**От задач предприятия — к обоснованной программе роботизации.** Платформа помогает определить, какие процессы роботизировать, какое оборудование выбрать и какой эффект оно даст конкретному объекту.

Четыре преимущества составляют основу продукта:

- **Процессно-ориентированное ядро.** Подбор начинается с задач и условий предприятия, а не с выбора робота в каталоге.
- **Самостоятельное развитие платформы.** Администратор добавляет и актуализирует сущности, связи, правила и настройки без программистов в рамках существующих механизмов.
- **Роботизация под ключ.** Единый цикл подготовки к внедрению: анализ процессов → подбор оборудования → расчёт парка → экономика и риски → план и отчёт.
- **Экосистема вендоров.** Производители участвуют в пополнении каталога и уточнении характеристик через собственный кабинет и модерацию заявок.

## Что отличает платформу

### Процессы определяют выбор

Потоки, маршруты, сменность, грузы и условия среды задают требования к каждому процессу. Один продукт может решать несколько задач, а для одной задачи сравниваются альтернативы разных производителей. Заказчик оценивает решения в контексте своей работы.

### Самостоятельное ядро и самообслуживание

Основа платформы — связанные сущности: **отрасли → объекты → процессы → типы решений → продукты**. Общие характеристики, правила и нормативы переиспользуются при расширении каталога и набора задач.

Админка объединяет управление этой моделью: от карточек и полей объекта до фильтров, формул количества, ранжирования и экономических нормативов. Правила можно проверить на параметрах объекта до сохранения. Обновление предметной модели становится повседневной работой администратора.

### Каталог развивается вместе с участниками

Вендор передаёт профиль компании, новые модели и обновления характеристик вручную или через импорт. Администратор проверяет заявки и публикует изменения. Аналитика участия моделей в подборе помогает определить, какие сведения нужно уточнить у производителя.

Так потребности заказчиков направляют развитие каталога, а поставщики получают понятный канал актуализации своих решений.

### Сквозное обоснование роботизации

В одном проекте пользователь проходит последовательность:

1. **Объект и процессы:** параметры площадки, задачи, исходные трудозатраты и требования.
2. **Технический подбор:** применимость решений, объяснение результатов, расчёт количества и сравнение допустимых альтернатив.
3. **Экономика:** сценарии «без роботизации», «покупка», «аренда/RaaS»; CAPEX, OPEX, ROI, TCO, окупаемость, NPV и IRR. Вложения учитывают также инфраструктуру, ПО, интеграцию, пусконаладку и обучение.
4. **What-if и риски:** изменение параметров, анализ чувствительности, интервалы оценок и стресс-сценарии.
5. **План и отчёт:** имитация смены на схеме объекта, печать в PDF, выгрузка таблиц для Excel и CSV.

Экономика раскрывается **по процессам и по выбранной программе в целом**. Модель учитывает общий персонал нескольких процессов и связывает эффект с исходными трудозатратами. Заказчик может менять состав программы и оценивать предложения по её корректировке с учётом бюджета.

### Результат можно проверить

**Техническая применимость, количество оборудования и экономический эффект** оцениваются последовательно. Это связывает инвестиционное обоснование с выбранными решениями и параметрами объекта.

Вердикты сопровождаются причинами, расчёты — формулами и подстановками, характеристики — источниками. Импорт и парсеры помогают актуализировать каталог, сохраняя ручные исправления.

Имитация на плане объекта показывает работу парка: маршруты, очереди, зарядку, пиковую нагрузку и отказы. Заказчик может оценить поведение выбранного решения ещё на этапе подготовки пилота.

## Масштабирование и развитие

**Текущий охват:** сквозные шаги интерфейса доступны для склада, аэропорта и медучреждения.

**Расширяемость архитектуры:** единая предметная модель позволяет пополнять платформу новыми роботами, процессами и объектами, используя существующие механизмы настройки и расчёта.

**Направления развития:** участие интеграторов, подключения к WMS/ERP и сохранение версий расчётов и каталога.

## Быстрый старт

Нужны Docker с Compose v2 и свободные порты 80 и 5432.

```bash
git clone <адрес репозитория> robots-platform
cd robots-platform
make up            # или: docker compose up -d --build
```

После запуска сайт: <http://localhost>. Вход: `admin` / `demo-2026` (также `user`, `guest`; кабинет вендора — `ronavi` с тем же паролем). Открыть демо «Склад Внуково-Юг» и пройти шаги «Подбор → Сравнение → Экономика → What-if → План → Отчёт».

Состав демонстрационного набора описан в разделе «Демо-данные». Для другого HTTP-порта: `make up HTTP_PORT=8080`.

Остановить: `make down`. Сбросить данные: `make reset`.

Развёртывание на сервере с Coolify: файл [docker-compose.coolify.yaml](docker-compose.coolify.yaml). Общие настройки — в [руководстве по развёртыванию](docs/03-deployment.md).

> Переключатель **«Визуальные эффекты»** в верхней панели позволяет выбрать оформление интерфейса. Выбор сохраняется в браузере.

## Сервисы

| Сервис | Назначение | Адрес |
|---|---|---|
| `traefik` | Единая точка входа | :80 |
| `web` | Nuxt 4 (Vue 3), страницы и имитация в браузере | `/` |
| `platform-api` | FastAPI: подбор, экономика, проекты | `/platform/api/v1` |
| `platform-worker` | Импорт каталога и парсеры | — |
| `db` | PostgreSQL 16 | :5432 |

Swagger UI: <http://localhost/platform/api/v1/docs>.

## Переменные окружения

Основные настройки локального запуска из `docker-compose.yaml` и настроек API:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | `postgresql+psycopg://robots:robots@db:5432/platform` | БД платформы |
| `POSTGRES_ADMIN_URL` | `…/postgres` | Создание базы при старте |
| `SESSION_SECRET` | `platform-demo-session-secret` | Подпись cookie. Сменить в проде |
| `UPLOAD_DIR` | `/app/uploads` | Фото карточек и подложки схем |
| `ROOT_PATH` | `/platform` | Префикс API за Traefik |
| `NUXT_PUBLIC_PLATFORM_API_BASE` | `/platform/api/v1` | Путь к API для сайта |
| `DEMO_SYNTHETIC_ENABLED` | `true` в текущем локальном Compose и настройках API | Подключение синтетического набора к выбранным демопроектам; `false` в окружении API отключает его |

Полный список: [docs/03-deployment.md](docs/03-deployment.md).

## Демо-данные

При первом запуске загружаются **555 карточек каталога** и три демопроекта: склад, аэропорт и медучреждение.

**Демонстрационные данные имеют отдельную маркировку.** Локальный Compose включает синтетический набор `demo_synthetic` для выбранных демопроектов. Он хранится отдельно от исходного каталога и содержит происхождение и пояснения значений.

Сценарии, инженерные модели и результаты проверок **30 процессов трёх объектов** описаны в [аудите демонстрационного контура](docs/22-demo-engineering-models.md).
