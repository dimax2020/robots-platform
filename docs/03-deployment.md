# Раздел 3. Развёртывание и запуск

*Закрывает пп. 6.2 и 6.10 ТЗ: третья сторона должна развернуть систему и воспроизвести демо-расчёт по этой инструкции без участия разработчиков.*

Порядок ниже проверен на чистой базе данных: команда запуска создаёт БД, применяет 14 миграций, загружает каталог (555 карточек, 65 процессов, 47 правил подбора) и создаёт три демо-проекта и три учётные записи; на это уходит около двух секунд.

## 3.1. Требования к окружению

| Что | Требование |
|---|---|
| ОС | Linux, macOS или Windows с WSL2. Разработка и проверка велись на macOS |
| Docker | Docker Engine 24 или новее с плагином Compose v2 (`docker compose`) |
| `make` | Необязательно; заменяется командой `docker compose up -d --build` |
| Свободные порты | `80` (Traefik) и `5432` (PostgreSQL, проброшен наружу для отладки) |
| Диск | Около 3 ГБ под образы и сборку; данные БД занимают десятки мегабайт |
| Сеть при первой сборке | Доступ к Docker Hub, `ghcr.io` (образ `uv`), PyPI и npm registry |
| Сеть при работе | Браузеру нужен доступ к Google Fonts (шрифты Unbounded, Manrope, JetBrains Mono). Без него интерфейс работает, но шрифты подменяются системными |
| Браузер | Актуальный Chrome, Edge, Firefox или Safari. Рабочее разрешение от 1366×768 заявлено в ТЗ на интерфейс, проверено на 1440×900 (раздел 12) |

Исходный код нужно получить из репозитория: `git clone <адрес репозитория>`; далее команды выполняются в корне репозитория.

## 3.2. Быстрый запуск

```bash
git clone <адрес репозитория> robots-platform
cd robots-platform
make up
```

Что делает `make up`: выполняет `docker compose up -d --build --remove-orphans`, ждёт, пока `GET /api/v1/health` начнёт отвечать, и печатает адреса. Без `make`:

```bash
docker compose up -d --build
```

Первая сборка образов занимает несколько минут (устанавливаются зависимости Python и Node). Повторный запуск с готовыми образами занимает секунды.

После запуска доступно:

| Адрес | Что открывается |
|---|---|
| <http://localhost> | Сайт платформы |
| <http://localhost/platform/api/v1/health> | Проверка API, ответ `{"ok":true}` |
| <http://localhost/platform/api/v1/docs> | Swagger UI |
| <http://localhost/platform/api/v1/openapi.json> | Схема OpenAPI |

## 3.3. Что происходит при первом запуске

1. Контейнер `db` создаёт кластер PostgreSQL и базу `robots` (том `pgdata`).
2. `platform-api` выполняет `python -m app.bootstrap`. Скрипт под advisory-lock (чтобы API и воркер не гонялись за БД одновременно) создаёт базу `platform`, если её нет.
3. Если в базе нет ни одного продукта, скрипт загружает снимок `platform/seed/platform.sql`, а затем применяет миграции Alembic до `0014_match_settings`. Если снимка нет, миграции запускаются на пустой базе и данные создаются из `seed_warehouse` и `reference_data`.
4. Учётные записи и три демо-проекта приходят со снимком и миграциями.
5. `platform-worker` повторяет `bootstrap` (он безопасен) и начинает читать очередь заданий.
6. `web` запускает собранный Nitro-сервер на порту 3000. Traefik направляет на него все пути, кроме `/platform`.

Повторный запуск не портит данные: если продукты в базе уже есть, выполняются только недостающие миграции.

## 3.4. Переменные окружения

Все переменные необязательны: значения по умолчанию подходят для локального запуска и заданы в `docker-compose.yaml`. Файл `.env` для запуска через Docker не нужен (`.env` есть в `.gitignore` для локальной разработки).

| Переменная | Сервис | По умолчанию | Назначение |
|---|---|---|---|
| `DATABASE_URL` | api, worker | `postgresql+psycopg://robots:robots@db:5432/platform` | Строка подключения к БД платформы |
| `POSTGRES_ADMIN_URL` | api, worker | `postgresql+psycopg://robots:robots@db:5432/postgres` | Подключение с правом создавать базу (для `bootstrap`) |
| `PLATFORM_DB_NAME` | api, worker | `platform` | Имя создаваемой базы |
| `UPLOAD_DIR` | api, worker | `/app/uploads` | Каталог загрузок (том `platform_uploads`) |
| `ROOT_PATH` | api | `/platform` | Внешний префикс за Traefik. Пусто, если API открыт напрямую |
| `SESSION_SECRET` | api | `platform-demo-session-secret` | Ключ подписи cookie сессии. **Для боевого запуска обязательно заменить** |
| `JOB_STALE_S` | worker | `1800` | Через сколько секунд зависшее задание считается брошенным |
| `LIST_PAGE_SIZE` | api | `24` | Размер порции карточек каталога |
| `NUXT_PUBLIC_PLATFORM_API_BASE` | web | `/platform/api/v1` | Путь к API относительно origin сайта |
| `NUXT_DEV_API_ORIGIN` | web (только dev) | `http://localhost` | Куда проксировать `/platform` при `npm run dev` |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | db | `robots` / `robots` / `robots` | Учётные данные PostgreSQL |

Примеры задания переменных: добавить строку в раздел `environment` сервиса в `docker-compose.yaml`, либо создать рядом с файлом `.env` и подставлять значения через `${VAR}` в compose.

## 3.5. Остановка, перезапуск, сброс

| Команда | Действие |
|---|---|
| `make ps` | Состояние контейнеров |
| `make logs` | Журналы api, worker и web |
| `make down` | Остановить, данные сохраняются |
| `make reset` | Остановить и **удалить тома**: следующий `make up` соберёт каталог заново из снимка. Все правки администратора и пользовательские проекты пропадут |

## 3.6. Что поменять перед публичным запуском

Прототип настроен для демонстрации. Для публичной установки нужно:

1. Задать собственный `SESSION_SECRET` и сменить пароль трёх демо-записей (сейчас у всех `demo-2026`, см. приложение Г).
2. Убрать проброс порта `5432` из `docker-compose.yaml` и сменить пароль PostgreSQL.
3. Поставить перед Traefik терминатор TLS или включить в Traefik entrypoint `websecure` с сертификатом. Cookie сессии без TLS передаётся открытым текстом.
4. Настроить резервное копирование томов `pgdata` и `platform_uploads`.

## 3.7. Локальная разработка без контейнеров для сайта

```bash
docker compose up -d db platform-api platform-worker traefik   # бэкенд и БД
cd frontend
npm ci
npm run dev                                                    # http://localhost:3000
```

В режиме `npm run dev` Nuxt проксирует `/platform/**` на `http://localhost` (то есть на Traefik в контейнере), поэтому cookie и пути совпадают с боевой схемой.

Тесты серверной части запускаются на машине разработчика (в образ `platform-api` тестовые зависимости не входят). Нужны `uv` и работающая БД из compose (порт 5432):

```bash
cd platform
uv run pytest -q
```

На дату документа проходит 148 из 149 тестов. Падает `tests/test_domain.py::test_classify_cleaner_and_forklift`: функция `classify` не относит строку «Уборочные роботы Cleanbotics поломоечная» к процессу `floor_cleaning`. Это дефект устаревшего теста или правила классификации по ключевым словам; на подбор и экономику по текущему каталогу он не влияет, так как процессы назначены карточкам в БД (раздел 12).

Проверка типов фронтенда: `cd frontend && npx nuxi typecheck`.

## 3.8. Как воспроизвести демо-расчёт

Порядок проверки, ожидаемые числа и допуски описаны в приложении Г (сценарий проверки). Минимальный путь:

1. `make up`, открыть <http://localhost>.
2. Открыть демо «Склад Внуково-Юг» (`/projects/demo-warehouse`).
3. Пройти шаги «Подбор → Сравнение → Экономика», выбрать роботов по сценарию из приложения Г.
4. Сверить CAPEX, OPEX, эффект и срок окупаемости с эталоном из приложения Г.

Те же числа воспроизводятся и без интерфейса вызовом `POST /projects/demo-warehouse/economy`; пример запроса дан в [api.md](api.md).

## 3.9. Диагностика

| Симптом | Причина и действие |
|---|---|
| Порт 80 занят | Остановить локальный веб-сервер или изменить `ports` у `traefik` в `docker-compose.yaml` (например, `8080:80`); тогда сайт будет на `http://localhost:8080` |
| `make up` печатает «Платформа не ответила» | Смотреть `docker compose logs platform-api`. Частая причина: БД не успела стартовать или образ не собрался из-за сети |
| Сайт открывается, каталог пуст | БД создана с ошибкой. Выполнить `make reset` и `make up` |
| Вход выдаёт «Нужна авторизация» после перезапуска | Изменился `SESSION_SECRET`: cookie старой подписью недействительна. Выйти и войти заново |
| Парсеры не запускаются | Воркеру нужен выход в интернет к сайтам-источникам. Каталог при этом работает |
