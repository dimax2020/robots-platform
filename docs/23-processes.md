# Процессы: как устроены и с чем связаны

**Процесс** — это работа на объекте, которую можно отдать роботу: перевозка паллет, комплектация заказов, инвентаризация, уборка, патрулирование, доставка лекарств, перевозка багажа и т. д. В справочнике 65 процессов на 18 типов объектов.

Платформа считает не «робота для склада», а «робота для конкретной работы». Поэтому процесс — единица, через которую связаны объект, подбор, количество, экономика, схема, отчёт и аналитика.

```
Тип объекта ──┐
              ├─► ПРОЦЕСС ──► правила подбора ──► роботы процесса ──► лучший робот
Проект ───────┘      │
                     ├─► модель количества (сколько роботов)
                     ├─► работа и люди (экономия, окупаемость)
                     ├─► объекты на схеме (визуализация)
                     └─► журнал подбора (аналитика вендора)
```

## 1. Справочник: что хранится у процесса

| Что | Где | Зачем |
|---|---|---|
| Код, название, описание | `process` | Описание показывается на шаге выбора процессов: что роботы сделают за людей |
| На каких объектах бывает | `object_process` (115 связей) | Объект сам предлагает свои процессы: склад — паллеты и комплектацию, больница — лекарства и биоматериалы |
| Какие роботы умеют | `product_process` (496 связей) | Круг кандидатов для подбора |
| Правила подбора | `process_filter` (47 правил) | Что сравнивать у робота и площадки и что делать, если не выполнено |
| Привязка входов к полям площадки | `object_input_binding` | Какое поле площадки этого объекта подставить в правило или формулу процесса |
| Формула количества и её входы | `process.count_formula`, `count_inputs` | Сколько роботов нужно |
| Кто лучший | `process.rank_key`, `rank_order` | По какой характеристике выбирать лучшего |
| Объекты схемы | `process.layout_items` | Что поставить на план для этого процесса |
| Модель количества и допущения | `process_assessment` | Инженерная модель числа роботов (6 моделей) |

## 2. Что настраивается в админке («Админка → Процессы»)

Редактор процесса — четыре шага с проверкой на примере.

1. **Условия подбора.** Название условия, характеристика робота, параметр площадки, сравнение (`==`, `<=`, `>=`, `<`, `>`) и режим:
   - **жёсткое** — не выполнено, значит «Не подходит»;
   - **условное** — не выполнено или нет данных, значит «Уточнить» с причиной.
2. **Сколько роботов нужно.** Формула и её входы, привязанные к полям площадки, и модель подбора: мобильный цикл, буксировка, стационарный цикл, площадь уборки, AS/RS, обработка поверхностей. Модель считает от суточного потока и выработки одного робота с учётом зарядки, доступности и резерва.
3. **Кто лучший.** Характеристика и направление, например наибольшая грузоподъёмность или наибольшая производительность. Если не задано — самый дешёвый. Лучшего выбирают только среди роботов, которые прошли все условия площадки и у которых известны цена и количество.
4. **Схема для визуализации.** Объекты процесса на плане:
   - роли: откуда берут, куда везут, зарядка, точка обхода, рабочая зона, препятствие;
   - форма: точка или зона;
   - минимальное количество;
   - правило количества: фиксированное, по потоку или по зарядке.

Там же процесс привязывается к объектам. Новый объект или процесс заводится без программиста.

## 3. Что настраивается в проекте

| Где | Что | Как хранится |
|---|---|---|
| Параметры → «Что роботизируем» | Какие процессы объекта включены | `project_process.enabled` |
| Параметры → «Работа и люди на процессах» | По каждому процессу: объём работ в сутки, сколько человек сейчас, зарплата одного в месяц | задача процесса в `project.site` (`flow_per_day`, `staff_fte_now`, `staff_salary_month_rub`) |
| Сравнение | Какой робот идёт в расчёт по процессу (по умолчанию — лучший) | выбор в браузере, передаётся в экономику |
| Экономика → процесс → «Настроить процесс» | Число роботов, цена от карточки, сервис, энергия, роботов на диспетчера, выработка робота | `economy_overrides`: `count:<код>`, `rate:<код>`, коэффициенты процесса |
| Экономика | Включить или выключить процесс в итоге | `off:<код>`, причина в `project_process.disabled_reason` |

«Подставить демо-данные» заполняет всё сразу: площадку и по каждому процессу — объём, людей и зарплаты из демо того же типа объекта. Дальше пользователь только правит.

## 4. Как процесс проходит через шаги

| Шаг | Что делает с процессом |
|---|---|
| **Параметры** | Включаем процессы, вводим объём работ, людей и зарплаты |
| **Подбор** | Роботы процесса проверяются по его правилам: «Подходит», «Уточнить» или «Не подходит», у каждого вердикта — причина. Модель считает количество |
| **Сравнение** | Характеристики роботов процесса бок о бок; выбранный робот закреплён слева |
| **Экономика** | Сначала каждый процесс отдельно: «почему этот робот, сколько, что в CAPEX», выработка человека против робота за год, кого заменяет робот, экономия, NPV, окупаемость. Потом — общая картина объекта |
| **What-if** | Допущения можно смотреть для всего объекта или для одного процесса |
| **Визуализация** | Объекты процесса на плане, смена с роботами, по каждому процессу «справляется / не успевает» |
| **Отчёт** | «Что роботизировать» по процессам, парк с причинами выбора, экономика процессов |

На шагах «Подбор», «Сравнение» и «Экономика» процессы стоят в боковой панели: статус и короткий итог шага. Выбранный процесс сохраняется при переходе между шагами. При первом прохождении процессы идут по порядку.

## 5. Экономика процесса

- **Работа.** У процесса есть единица и вид работы: перемещение, обход, площадь или сканирование. Например, «паллеты в сутки» для перевозки и «м² уборки» для уборки.
- **Выработка.** Сравнивается выработка человека за год (норма ТК РФ) и робота (часы площадки × готовность 0,82 × производительность по карточке). Отсюда — сколько людей заменяет робот и какую долю операций он закрывает.
- **Экономия.** Уходит столько людей, сколько робот реально закрывает, целыми ставками в каждой смене.
- **Общие люди.** Если два процесса делают одни и те же люди, их не считают дважды: «те же люди уже уходят с другого процесса».
- **Затраты без людей.** Если людей не знают, можно ввести затраты на процесс суммой.

**Платформа сама правит состав** (`auto:count:`, `auto:off:`). Она подбирает число роботов на процессе и убирает невыгодные процессы так, чтобы NPV объекта был наибольшим в пределах бюджета. Пользователь видит, что поменялось и почему, и может вернуть одной кнопкой. Скидки вендора и господдержку она сама не включает — только подсказывает, что сделает процесс выгодным.

## 6. Условия демо

У демо-объектов есть набор условий расчёта по процессам: `seed/demo_synthetic.json`. В нём:
- объём, люди и зарплаты;
- условия рабочей зоны (температура, шум, автономность);
- комплектации роботов;
- коэффициенты затрат.

Обычный проект берёт условия демо того же типа объекта (`template_plan`). Они только заполняют пробелы: всё, что ввёл пользователь, сильнее. Поэтому новый проект считается так же полно, как демо.

## 7. Процесс в аналитике и для партнёров

- **Журнал подбора** (`match_journal`). Каждый запуск подбора записывается по процессам, без данных заказчика: кто прошёл, кто нет и почему.
- **Вендор.** Из журнала вендор видит, в каких процессах участвуют его роботы, сколько раз их показали, где подбор не сложился и каких характеристик не хватило.
- **Интегратор.** Получает проект целиком: процессы с выбранными роботами, экономику и схему. Оценивать можно по процессам.
