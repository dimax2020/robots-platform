# Аудит перехода от технического допуска к экономике

> Снимок до добавления инженерных моделей. После доработки доступны 62 из 62 альтернатив: [результат и модели](22-demo-engineering-models.md).

Проверка локального DEV от 20 октября 2026 года. Проверены все **3 объекта, 30 процессов и 62 технически подходящие альтернативы**. Единица счёта — сочетание объект / процесс / карточка: один робот в разных процессах учитывается отдельно. Все положительные решения условны (`verdict=pass`, `applicability=conditional`).

Из 62 альтернатив **47 уже были доступны экономике**, а **15 были недоступны**. После проверки и обновления DEV эти числа сохранились: **дополнительно подключено 0 из 15**. У всех 15 нет применимой модели количества; заполнение характеристик и параметров операции это не устраняет. У семи дополнительно явно неполная комплектация, у трёх из этих семи не подтверждён состав цены системы.

Все 47 доступных альтернатив выбраны по HTTP через штатный `picks`, включая **28 замен робота по умолчанию**. Для каждой подтверждены нужный ID, вычисленное количество, включение в парк, сохранение допущений и данных sizing, полный расчёт и наличие трёх сценариев. Ошибок выбора нет. Выбор платформы не ограничивает набор экономически допустимых альтернатив.

`complete` относится к зарегистрированной программе роботизации внутри объекта. Процессы без применимой модели остаются вне её расчёта; это не полнота экономики всех 30 процессов.

## Причина каждого из 15 недопусков

Категории пересекаются. В этом состоянии DEV нет подходящей альтернативы, блокируемой только недостающими характеристиками робота, параметрами операции, ценой в рублях или входами действующей модели количества. Все 15 блокируются математической моделью. Для семи известное `configuration_complete=false` сохранено; синтетический `true` не подставлен. Цены карточек положительны, однако полнота цены AS/RS не установлена.

## Передача разработчикам моделей

Проверены действующий реестр `domain/sizing.py`, привязки в `domain/demo_synthetic.py` и реальные `process.count_formula` в DEV. Пустая или неподходящая сохранённая формула не становится применимой от подстановки синтетической скорости.

| Процесс / класс | Почему нельзя использовать существующее выражение | Что требуется для будущей модели |
|---|---|---|
| Хранение и выдача / AS/RS | Сохранён транспортный маршрут `2 * picker_route_m / robot.speed_loaded_ms + 80`; он не описывает ёмкость системы и циклы кранов/шаттлов | Конфигурация модулей и ярусов, число мест, циклы ввода/вывода и пропускная способность |
| Комплектация / AS/RS | Формула считает маршрут мобильного комплектовщика; технический pass получен системами AS/RS | Станции отбора, строки заказа, циклы выдачи контейнеров и ограничения подачи |
| Паллетирование / стационарные манипуляторы | Сохранён транспортный маршрут, отсутствует модель цикла ячейки | Схема укладки, захват, подача, цикл изделия/слоя/паллеты, состав поставки |
| Упаковка / стационарные ячейки | Сохранён транспортный маршрут, не цикл упаковки | Подача изделий, такт упаковки, смена формата, оснастка и состав линии |
| Фасады / воздушная мойка | `count_formula` пустая; `cleaning_area_v1` предназначена для напольной уборки | Площадь фасада, высота, перестановки, вода, вылеты и рабочая погода |
| Кровля / БПЛА | Сохранён наземный патруль `24 * (4 * sqrt(area_m2) / robot.speed_loaded_ms + 240)` | Геометрия кровли, программа съёмки и перекрытие, вылеты, батареи, погода |

Новые формулы не разработаны и не подключены. Правила технического подбора, количество, CAPEX/OPEX, ROI и экономические нормативы не изменялись.

## Данные и DEV

Использованы существующие паспортные сведения, ранее заведённые рабочие режимы и явно маркированные DEV-входы. Новые численные допущения не потребовались: для всех 47 альтернатив с применимой моделью входов уже достаточно, а оставшиеся 15 требуют разработки моделей. Дописывать им числа ради снятия сообщения об отсутствии модели было бы неверно. Исходные характеристики, ограничения, цены и возможность вендорского уточнения сохранены.

В `seed/demo_synthetic.json` добавлены только пояснения `sizing_limitation`. Они выводятся в `sizing.reasons`, `economic_reasons` и уточнениях существующего интерфейса; сообщения различают отсутствие модели и необходимость дополнительных сведений. Проверка до/после подтвердила неизменность всех прочих полей манифеста, 62 положительных кандидатов, их количеств, допусков и коммерческих фактов. Контрольные суммы 14 исходных таблиц совпали: каталог, источники, связи, процессы, правила, привязки, проекты, assessment и настройки экономики сохранены.

DEV пересобран и доступен на **http://localhost:8080**: API, worker и web работают, health отвечает. Порт 80 занят другим локальным сервисом. Проверки backend выполнялись в отдельной временной копии PostgreSQL: **129 тестов прошли**. Общие сценарии выбора TypeScript и production-сборка web прошли. Полный backend-набор не запускался.

Дополнительно функции фронтенда `eligibleForEconomy` и `includedInTechnicalComparison` проверены на реальных HTTP-ответах всех трёх объектов: все 47 альтернатив доступны для выбора, включая 28 альтернатив выбору по умолчанию; у остальных 15 выбор блокируется с конкретными причинами.

Повторить аудит всех альтернатив через рабочий HTTP:

```bash
python3 platform/tools/check_demo_coverage.py \
  --http-base http://localhost:8080/platform/api/v1 \
  --verify-economy --output docs/demo-economy-audit.json
```

Альтернатива — существующий READ ONLY-режим аудита через DB: `PYTHONPATH=. python tools/check_demo_coverage.py --verify-economy` из каталога `platform`. HTTP-режим обновляет только штатную статистику показов. При расхождении флага готовности с реальным экономическим выбором скрипт сохраняет диагностику и завершается с ошибкой.
