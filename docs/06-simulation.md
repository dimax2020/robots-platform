# Раздел 6. Имитационная модель и визуализация

*Закрывает пп. 3.6.1–3.6.7 ТЗ. Исходный код: `frontend/app/sim/`, страница `frontend/app/pages/projects/[id]/plan.vue`.*

## 6.1. Назначение

Имитация проверяет, справится ли расчётный парк со сменой на плане конкретного объекта, и делает результат наглядным: роботы движутся по схеме, берут и отвозят грузы, стоят в очередях, заряжаются. Она отвечает на вопрос «подтверждает ли поведение парка расчётное число роботов», а не даёт точный прогноз производительности.

Имитация выполняется целиком **в браузере**: сервер получает и хранит только схему расстановки. Расчёт смены запускается в Web Worker (`sim/worker.ts`), поэтому интерфейс не блокируется; в фоновом потоке вычисляется и минимальное число роботов, которое подтверждает поток.

## 6.2. Схема объекта

Схема хранится в проекте (`project.layout`, JSON версии 1) и включает:

| Элемент | Что это |
|---|---|
| Этаж | Размеры в метрах, участки пола (`areas`), стены, препятствия (`blocks`), станции, зоны, подложка |
| Участки пола | Полигоны, внутри которых ездят роботы. Стена — это граница участка |
| Станция | Точка процесса: погрузка (`load`), выгрузка (`unload`), зарядка (`charge`), путевая точка (`waypoint`) |
| Зона | Прямоугольник обработки, например зона уборки |
| Переход | Лифт или лестница: два конца на разных этажах, время ожидания и время на этаж |
| Подложка | Загруженный чертёж (PNG, JPG, WebP до 20 МБ) с масштабом, задаваемым по известному размеру, прозрачностью и блокировкой |

Редактор работает в двух режимах: «Здание» (этажи, участки, препятствия, лифты, подложка) и «Роботы» (станции, зоны, объекты процессов). Для процессов определены шаблоны объектов (`layout_items`): например, у перевозки паллет это пункт погрузки, пункт выгрузки и зарядная станция, для каждого указано минимальное количество и правило числа (`fixed`, `by_flow`, `by_charge`). Схему можно выгрузить картинкой PNG.

## 6.3. Что и как моделируется

Модель дискретно-событийная с фиксированным шагом времени $\Delta t = 0{,}5$ с (`STEP_S`). Тип процесса определяет поведение:

| Тип | Пример | Поведение |
|---|---|---|
| `transport` | Перевозка паллет, доставка грузов | Задания поступают потоком, робот едет к пункту погрузки, грузится, едет к выгрузке, разгружается, при необходимости заряжается |
| `coverage` | Уборка, инвентаризация | Робот покрывает зону со скоростью, ограниченной производительностью, если она задана |
| `patrol` | Охрана, патрулирование | Робот ездит по замкнутому маршруту и останавливается на путевых точках |

Ключевые элементы модели:

- **Поток заданий.** Для `transport` задания приходят как пуассоновский поток: интервал между ними случайный с экспоненциальным распределением, интенсивность $\lambda = \dfrac{Q_{ч}}{3600}$, где $Q_{ч}$ — требуемое число заданий в час (то же, что в формуле количества роботов, раздел 4.4). Генератор случайных чисел детерминированный (seed 20260926), поэтому прогон воспроизводим.
- **Маршруты.** Кратчайший путь ищет алгоритм A\* (библиотека `pathfinding`) на сетке с шагом 1 м, диагональные ходы разрешены только при отсутствии препятствий. Между этажами робот едет на лифте или по лестнице; лестницы доступны только роботам, у которых это заложено в параметрах.
- **Скорость** берётся из карточки робота (`speed_loaded_ms`). Если её нет, используется значение по умолчанию, и в примечании к процессу это указано («Скорости в карточке нет, взято … м/с»).
- **Погрузка и выгрузка** занимают заданное время; на станции может быть очередь, роботы ждут.
- **Батарея.** Запас хода равен времени работы из карточки (с разбросом начального заряда 55–100 %). При падении ниже 20 % робот едет на зарядку; длительность зарядки пропорциональна недостающему заряду и времени полной зарядки из карточки. Свободный робот с зарядом ниже 50 % подзаряжается, если есть свободная зарядная станция без очереди.
- **Отказы.** В живом режиме кнопка «Сломать» выводит случайного робота из строя, груз возвращается в очередь; «Починить» и «Все в строй» возвращают роботов. Режим «сбой» (`failure`) в движке также умеет отключать заданную долю парка на весь прогон.
- **Пиковая нагрузка.** Движок поддерживает множитель потока `peak` (по умолчанию из параметра площадки `peak_factor`). В интерфейсе поток меняется ползунком «Поток заданий» от 30 % до 250 % базового.

## 6.4. Что показывает визуализация

На экране «Визуализация» (ТЗ 3.6.4) доступны:

- анимированная схема с роботами, их статусами (свободен, едет, с грузом, обслуживается, в очереди, заряжается, в лифте, работает, выведен из строя) и уровнем заряда;
- список маршрутов «сейчас»: откуда, куда, сколько метров осталось; по клику камера следит за роботом;
- монитор: кольцо загрузки, число роботов в строю и сломанных, очередь, выполнено в час, число не взятых заданий, загрузка роботов, разбивка по процессам;
- для каждого процесса метка «Подтверждает расчёт» или «Не подтверждает расчёт» и минимально необходимое число роботов, найденное перебором.

## 6.5. Критерий «подтверждает расчёт»

Прогон считается устоявшимся, когда прошло не менее 30 минут модельного времени. Для процесса-перевозки условие подтверждения:

$$\text{очередь заданий} \le \max\left(3,\ 900 \cdot \lambda\right) \quad\text{и}\quad \text{выполнено} > 0$$

то есть невыполненных заданий накопилось не больше, чем поступает за 15 минут. Для остальных типов процессов:

$$\frac{\text{выполнено}}{\text{часов}} \ge 0{,}95 \cdot Q_{ч}$$

Показатели процесса, которые платформа показывает: число роботов, в строю, вышло из строя, в очереди, требуемое и фактическое число операций в час, невыполненные задания, загрузка (доля времени занятости), доля времени на зарядке, среднее время ожидания и максимальная очередь, среднее время цикла.

## 6.6. Связь с расчётом подбора и экономики

Число роботов и время цикла берутся из результатов подбора (формулы количества) и карточки робота. Имитация **не обратно** влияет на экономику: если она показывает «Не подтверждает расчёт» или подсказывает другое минимальное число роботов, стоимость парка в экономике не пересчитывается автоматически. Пользователь видит расхождение и при желании меняет парк на шаге сравнения (раздел 12).

## 6.7. Допущения и ограничения

- Роботы не блокируют друг друга при движении: столкновения и объезд не моделируются, конфликты возникают только на станциях в виде очередей. Это допущение сознательно: для экспресс-оценки важнее поток и очереди, чем физика.
- Сетка 1 м. Узкие проходы уже 1 м на схеме нужно рисовать шире.
- Все задания одинаковые; вариация только во времени поступления. Различий по приоритету, габаритам и несовместимости грузов нет.
- Зарядка упрощена: одинаковая для всех роботов процесса, без очереди приоритетов.
- Смена целиком считается на одном ядре браузера; для очень больших парков (сотни машин) расчёт заметно медленнее.
- Экономика и визуализация на демо-объектах: у демо-проектов схема расстановки в поставке не сохранена, поэтому шаг «Визуализация» на демо открывается пустым, пока администратор не расставит станции. Пользователь может скопировать демо к себе и нарисовать схему (приложение В).
