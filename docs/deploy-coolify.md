# Развёртывание в Coolify

Инструкция для Coolify v4. На сервере с Coolify уже работает собственный прокси (Traefik): он занимает порты 80 и 443 и выпускает сертификаты Let's Encrypt. Поэтому обычный `docker-compose.yaml` со своим Traefik здесь не подходит: два Traefik будут бороться за одни и те же порты. Для Coolify в репозитории лежит отдельный файл `docker-compose.coolify.yaml`.

## Чем отличается файл для Coolify

| | `docker-compose.yaml` (локально) | `docker-compose.coolify.yaml` |
|---|---|---|
| Прокси и TLS | свой Traefik на порту 80, без TLS | прокси Coolify, HTTPS с сертификатом |
| Путь `/platform/**` | Traefik снимает префикс и отправляет в API | сайт (`web`) сам проксирует в `platform-api` по внутренней сети |
| Наружу открыт | порты 80 и 5432 | только сайт через домен, база и API закрыты |
| Пароль БД и секрет сессии | зашиты демо-значения | задаются переменными в Coolify, без них запуск не стартует |

Браузер по-прежнему ходит на один домен: сайт на `/`, API на `/platform/api/v1`. Cookie сессии живёт на том же домене, CORS не нужен.

## Что понадобится

1. Сервер с установленным Coolify v4 и доступом к Docker Hub, `ghcr.io`, PyPI и npm (при сборке образов).
2. Домен, например `robots.example.ru`, с A-записью на IP сервера.
3. Репозиторий с этим кодом, доступный Coolify: публичный GitHub, GitHub App или любой git по deploy key.
4. Около 3 ГБ диска под образы и 2 ГБ оперативной памяти на время сборки фронтенда.

## Шаг 1. Отправить код в репозиторий

Файлы `docker-compose.coolify.yaml` и `frontend/server/routes/platform/[...path].ts` должны попасть в ветку, из которой Coolify будет собирать проект:

```bash
git add -A
git commit -m "Coolify: compose без собственного traefik"
git push origin2 main
```

## Шаг 2. Создать ресурс

1. В Coolify откройте проект (или создайте новый) и нажмите **+ New → Resource**.
2. Выберите источник: **Public Repository**, **Private Repository (with GitHub App)** или **Private Repository (with Deploy Key)** и укажите адрес репозитория и ветку.
3. В поле **Build Pack** выберите **Docker Compose**.
4. **Base Directory**: `/`.
5. **Docker Compose Location**: `/docker-compose.coolify.yaml`.
6. Нажмите **Continue**. Coolify прочитает файл и покажет четыре сервиса: `web`, `db`, `platform-api`, `platform-worker`.

## Шаг 3. Домен

Домен задаётся **только** сервису `web`. В поле **Domains** у `web` введите:

```
https://robots.example.ru:3000
```

`:3000` — это не порт в адресе сайта, а внутренний порт Nuxt в контейнере. Так Coolify понимает, что запросы с 443 надо отправлять на 3000. Снаружи сайт откроется по `https://robots.example.ru` без порта.

У `db`, `platform-api` и `platform-worker` поле домена оставьте пустым: они должны быть доступны только внутри сети проекта.

## Шаг 4. Переменные окружения

Откройте вкладку **Environment Variables**. Coolify сам покажет две переменные из compose-файла, их нужно заполнить:

| Переменная | Что указать |
|---|---|
| `POSTGRES_PASSWORD` | Пароль базы. Любая длинная строка без символов `@`, `:` и `/`: он подставляется в адрес подключения |
| `SESSION_SECRET` | Ключ подписи cookie входа. Сгенерируйте: `openssl rand -hex 32` |

Если оставить любую из них пустой, развёртывание остановится с сообщением «Задайте … в переменных Coolify».

Пароль базы записывается в том при **первом** запуске. Если сменить `POSTGRES_PASSWORD` позже, у уже созданной базы пароль не изменится, и API перестанет подключаться. Менять его надо в самой базе (`ALTER USER robots PASSWORD '…'`) и затем в переменной.

## Шаг 5. Развернуть

Нажмите **Deploy**. Первая сборка занимает несколько минут: ставятся зависимости Python и Node, собирается фронтенд. Затем при первом старте API создаёт базу `platform`, загружает каталог (555 карточек), применяет миграции и заводит три демо-проекта.

Проверка после развёртывания:

| Адрес | Ожидаемый ответ |
|---|---|
| `https://robots.example.ru` | Главная страница платформы |
| `https://robots.example.ru/platform/api/v1/health` | `{"ok":true}` |
| `https://robots.example.ru/platform/api/v1/docs` | Swagger UI |
| `https://robots.example.ru/projects/demo-warehouse` | Демо-склад |

Вход: `admin`, `user` или `guest`, пароль у всех `demo-2026`. Для публичного сервера смените пароли сразу после первого входа.

## Обновление

Отправьте изменения в ветку и нажмите **Redeploy** в Coolify. Для автоматического развёртывания включите **Auto Deploy** (с GitHub App) или добавьте webhook из вкладки **Webhooks** в настройки репозитория.

Данные при обновлении сохраняются: база и загруженные файлы лежат в томах `pgdata` и `platform_uploads`. Новые миграции применяются при старте API сами.

## Резервная копия базы

Coolify делает автоматические бэкапы только для баз, созданных как отдельный ресурс. Здесь база входит в compose, поэтому копию снимают вручную. На сервере:

```bash
docker ps --format '{{.Names}}' | grep db        # имя контейнера базы
docker exec <имя-контейнера-db> pg_dump -U robots platform > platform-$(date +%F).sql
```

Восстановление в чистую базу:

```bash
docker exec -i <имя-контейнера-db> psql -U robots platform < platform-2026-09-29.sql
```

## Если что-то не работает

| Симптом | Причина и что сделать |
|---|---|
| `502 Bad Gateway` на домене | В домене `web` не указан порт `:3000`, и Coolify шлёт запросы на порт 80. Исправьте домен и сделайте Redeploy |
| Сайт открывается, но каталог пуст и вход не работает | API ещё стартует или упал. Смотрите логи `platform-api` во вкладке **Logs** |
| `404` на `/platform/api/v1/...` | Собран старый фронтенд без файла `frontend/server/routes/platform/[...path].ts`. Проверьте, что он есть в ветке |
| В логах API `password authentication failed` | `POSTGRES_PASSWORD` изменили после первого запуска. См. шаг 4 |
| Сборка падает на `TLS handshake timeout` или `failed to fetch` | Сервер не достучался до Docker Hub, PyPI или npm. Повторите Deploy |
| Сертификат не выпускается | A-запись домена ещё не указывает на сервер или закрыты порты 80 и 443 |
| Парсеры каталога не запускаются | Воркеру нужен выход в интернет к сайтам-источникам. Каталог при этом работает |
