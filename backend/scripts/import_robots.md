В консоль выводятся созданные и обновлённые роботы с перечнем добавленных полей,
а в конце — количество уникальных обновлённых роботов. При `--dry-run` это
число роботов, которые были бы обновлены, без сохранения изменений.
Полный JSON-отчёт, включая пропуски, можно сохранить через `--report`.

Импорт дополняет только текущие записи `product` (`valid_to IS NULL`). Имена
сравниваются без регистра и скобок, кириллица приводится к латинице. Совпадение —
когда последовательность слов одного имени целиком входит в другое.
`Ronavi H1500` находит `Ronavi H1500 (Россия)`, `AK-2000-2` находит
`AUTOMACON AK-2000-2`, `БРО 2.1` находит `168robotics BRO 2.1`.
Имя короче пяти символов не склеивается. Несколько совпадений в БД — `ambiguous`,
без обновления и без создания.
Для robob2b нет совпадения — `not_found`, новый продукт не создаётся.
Для robort.ru робот без совпадений создаётся, если указана корректная
положительная цена; подробности ниже.

Маппинг задан в `MAPPING` и `COLUMNS` файла `import_robots.py`:

- `specs → Общие характеристики → Бренд` → `manufacturer`;
- `specs → Общие характеристики → Страна производства` → `country`;
- технические параметры → `attrs[key]` в формате `AttrValue`;
- `url` → `source.url`, вид источника `catalog`, ссылка через `source_id`;
- `png_url` → `product.png_url`, только если поле пустое;
- `id` парсера не заменяет UUID продукта; `integrators` и характеристики
  без однозначного соответствия попадают в `skipped` подробного отчёта.

Колонки заполняются только вместо NULL, пустой строки или строки из пробелов.
В `attrs` добавляются только отсутствующие ключи. Существующие словари целиком
сохраняются, включая `unknown`, пустые значения, нули и `false`.
Числа с десятичной запятой поддерживаются; диапазоны и пояснения не превращаются
в точное число. кВт переводятся в Вт, мм ширины проезда — в метры.
Повторяемость манипулятора не подменяет точность позиционирования; максимальная
скорость без указания загрузки не подменяет скорость с грузом/без груза.
Перед записью проверяются тип и единица в справочнике `attribute_def` БД.

Из корня проекта с запущенной БД, после установки зависимостей backend:

```bash
cd backend
python -m scripts.import_robots ../robots.json --dry-run --report /tmp/robots-preview.json
python -m scripts.import_robots ../robots.json --report /tmp/robots-import.json
```

Через Docker Compose из корня проекта (собрать образ с новым скриптом):

```bash
docker compose build api
docker compose run --rm api alembic upgrade head
docker compose run --rm -v "$PWD/robots.json:/tmp/robots.json:ro" api python -m scripts.import_robots /tmp/robots.json --dry-run
docker compose run --rm -v "$PWD/robots.json:/tmp/robots.json:ro" api python -m scripts.import_robots /tmp/robots.json
docker compose restart api
```

Все изменения выполняются одной транзакцией. Текущие продукты блокируются до
её завершения, поэтому импорт лучше запускать вне массового редактирования.
`--dry-run` откатывает изменения (последовательность ID источников PostgreSQL
может продвинуться). При ошибке до commit изменения откатываются при закрытии сессии.
После применения нужно перезапустить API, чтобы обновить снимок каталога движка.

Ежедневное расписание работает внутри сервиса `parser` в Docker Compose.
`make up` собирает и запускает его вместе с проектом. Контейнер ждёт 03:00
Europe/Moscow, затем выполняет парсинг и импорт. Час и часовой пояс задаются
переменными `PARSER_HOUR` и `PARSER_TIMEZONE` в Compose. При старте немедленного
парсинга нет; пропущенные во время остановки запуски не воспроизводятся.

Результат сохраняется в `data/robots.json`. После успешного импорта обновляется
маркер `data/.catalog-refresh`; все процессы API перечитывают каталог в течение
30 секунд. Ошибка завершения парсера отменяет импорт; планировщик записывает
ошибку в лог и ждёт следующего дня. Перехваченные самим парсером ошибки отдельных
HTTP-запросов по-прежнему могут привести к частичной выгрузке.
Общий файловый lock предотвращает одновременный ручной и плановый запуск.

```bash
make up                     # запуск проекта вместе с расписанием
make parse                  # выполнить парсинг и импорт сейчас
docker compose logs -f parser
```

Настройки systemd и cron на хосте не требуются. Прямой запуск `parser.py`
собирает только JSON; `run.py --once` выполняет парсинг и импорт один раз.

Дополнительно поддерживается `robort.ru`: плоский `specs` из `robort_robots.json`
распознаётся автоматически. Цена записывается в `attrs.price_rub`, изображение —
в `png_url`. Вес, нагрузка, время, мощность и ширина проезда переводятся в единицы
каталога. Диапазоны, неоднозначные единицы и неизвестные характеристики отражаются
в `skipped`; заполненные данные по-прежнему сохраняются.

```bash
cd backend
python -m scripts.import_robots ../robort_robots.json --dry-run --report /tmp/robort-preview.json
python -m scripts.import_robots ../robort_robots.json --report /tmp/robort-import.json
```

Контейнер `parser` и `make parse` теперь последовательно обрабатывают оба сайта.
Вторая выгрузка сохраняется в `data/robort_robots.json` (путь можно изменить через
`ROBORT_OUTPUT_FILE`). Ошибка одного источника не мешает обработке другого.
Для применения изменений пересоберите сервис: `docker compose up -d --build parser`.
Корневой `python3 parser.py` запускает только сбор robort.ru; реализация находится
в `backend/parser/robort.py`. При критической ошибке сохраняется checkpoint,
но процесс завершается с ошибкой, и автоматический импорт этой выгрузки не запускается.

Создание из robort.ru: если текущего продукта с совпадающей последовательностью слов нет,
положительная цена позволяет создать новую запись. Несколько совпадений дают
`ambiguous`, новый робот в этом случае не создаётся. Нулевая, отрицательная,
отсутствующая или некорректная цена не разрешает создание. Требуются URL robort.ru
и совместимое определение `price_rub` в справочнике атрибутов.

Тип решения определяется по названию, типу и категории URL; при отсутствии
соответствия используется `robotic_installation`. Производитель — `Не указан`,
страна не заполняется, доступность — `operation` (каталожное предложение с ценой).
При первом создании в импорте создаётся версия каталога. UUID и slug вычисляются
из URL: повторный импорт того же URL не создаёт дубль даже при смене названия.
Архивная запись с этим slug не восстанавливается автоматически (`archived`).
Импорты сериализуются транзакционной advisory-блокировкой PostgreSQL.

В отчёте новые записи имеют статус `created`; консоль отдельно показывает число
созданных роботов. `--dry-run` откатывает и новые продукты, и новую версию, и источники.
